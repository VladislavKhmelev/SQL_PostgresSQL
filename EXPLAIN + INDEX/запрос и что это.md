EXPLAIN
SELECT *
FROM users
WHERE email = 'user99999@mail.ru';


 Index Scan using idx_users_email on users  (cost=0.42..8.44 rows=1 width=31)
   Index Cond: (email = 'user99999@mail.ru'::text)
(2 строки)


то PostgreSQL не выполняет сам SELECT.

Он только говорит:

«Вот какой план я собираюсь использовать, если ты действительно запустишь этот запрос».

Например:

Seq Scan on users
(cost=0.00..2074.00 rows=1 width=31)

Здесь ты получаешь оценку PostgreSQL:

Seq Scan → планирует последовательно читать таблицу;
cost → предполагаемая стоимость;
rows=1 → ожидает примерно 1 строку;
width=31 → ожидаемый размер строки.

Но ты не увидишь:

actual time
actual rows
loops
Buffers
Execution Time

Потому что запрос ещё не выполнялся.


Сравни:

EXPLAIN:

EXPLAIN
SELECT ...

→ только планирует и показывает план.

EXPLAIN ANALYZE:

EXPLAIN ANALYZE
SELECT ...

→ строит план + реально выполняет запрос + показывает фактические результаты.


Поэтому для нашего эксперимента с индексом:

EXPLAIN
↓
посмотреть, какой план PostgreSQL ПЛАНИРУЕТ использовать


EXPLAIN ANALYZE
↓
посмотреть, что ПРОИЗОШЛО НА САМОМ ДЕЛЕ
