Да, в нашем новом проекте мы предполагаем, что исходные таблицы уже существуют в PostgreSQL и являются нормализованным/очищенным источником:

suppliers
products

То есть у них уже есть правильные типы данных (INT, TEXT, NUMERIC, DATE/TIMESTAMP и т. д.), и мы не занимаемся здесь первичной очисткой CSV/JSON.

target — это роль таблицы в конкретной загрузке, а CORE — архитектурный слой.

В итоге архитектура нашего проекта

# ┌──────────────────────────────────────────────────────────────┐
# │                    SOURCE PostgreSQL                         │
# │                                                              │
# │              suppliers        products                       │
# │                   │               │                          │
# │                   └───────┬───────┘                          │
# │                           ↓                                  │
# │                 VALIDATION / TRANSFORMATION                  │
# │                           ↓                                  │
# │                    ┌──────┴──────┐                           │
# │                    ↓             ↓                           │
# │                   CORE          ERROR                        │
# │                    ↓             ↓                           │
# │             target_products  error_products                  │
# │                    ↓                                         │
# │                   MART                                        │
# │                    ↓                                         │
# │              products_mart                                   │
# └──────────────────────────────────────────────────────────────┘
У нас есть две исходные таблицы PostgreSQL:

products
suppliers

Они уже:

очищены технически;
имеют правильные типы данных;
но валидация бизнес-правил ещё не проведена.

Дальше для каждой исходной таблицы делаем свою обработку

То есть:

products

Из исходной products:

проверяем бизнес-правила;
проверяем дубликаты;
ошибочные строки → error_products;
валидные строки → CORE products.
# ┌──────────────────────────────────────────────────────────────┐
# │                 SOURCE PostgreSQL                            │
# │                                                              │
# │        products                    suppliers                 │
# │           │                           │                      │
# │           ↓                           ↓                      │
# │       VALIDATION                  VALIDATION                 │
# │           │                           │                      │
# │      ┌────┴────┐                 ┌────┴────┐                │
# │      ↓         ↓                 ↓         ↓                │
# │   VALID       ERROR           VALID       ERROR              │
# │      ↓         ↓                 ↓         ↓                │
# │  products  error_products    suppliers  error_suppliers     │
# │      │                           │                           │
# │      └──────────────┬────────────┘                           │
# │                     ↓                                        │
# │                  SQL JOIN                                    │
# │                     ↓                                        │
# │                    MART                                      │
# └──────────────────────────────────────────────────────────────┘

Потом MART

И уже две очищенные CORE-таблицы:

# products ────────┐
#                  ├──→ JOIN → MART
# suppliers ───────┘


То есть аналитическая таблица будет строиться из валидных products + валидных suppliers, а ERROR-таблицы в аналитический слой не идут.


Поэтому предлагаю:

исходные: source_products, source_suppliers
ошибки: error_products, error_suppliers
валидные CORE: products, suppliers
аналитика: products_mart
