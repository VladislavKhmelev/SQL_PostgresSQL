JOIN + индексы.

EXPLAIN ANALYZE
│
├── cost
├── rows
├── actual time
├── actual rows
├── loops
├── width
├── Index Cond
├── Filter
├── Rows Removed by Filter
└── Buffers


сделаем эксперимент с JOIN: сначала без индекса на orders.user_id, потом с индексом.

Предположим, у нас:

users.id — PRIMARY KEY, индекс уже есть;
orders.user_id — поле, по которому соединяем таблицы;
у одного пользователя может быть много заказов.
1. Вариант БЕЗ индекса на orders.user_id

Если индекс уже существует, удаляем его:

DROP INDEX IF EXISTS idx_orders_user_id;

Потом:

EXPLAIN ANALYZE
SELECT u.id, u.email, o.id, o.amount
FROM users u
JOIN orders o
    ON u.id = o.user_id
WHERE u.id = 99999;

Что мы сравниваем

Без индекса:

Seq Scan
↓
просматриваем orders
↓
Filter

С индексом:

Bitmap Index Scan
↓
Bitmap Heap Scan

И в обоих случаях сам JOIN остаётся:

Nested Loop


И обязательно сравни в выводе:

actual time
actual rows
loops
Buffers

— именно по ним мы увидим, насколько вариант с индексом оказался эффективнее.
