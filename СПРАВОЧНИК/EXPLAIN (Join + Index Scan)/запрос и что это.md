EXPLAIN

join + index



Без индекса

Сначала:

DROP INDEX IF EXISTS idx_orders_user_id;

Потом только смотрим план, не выполняя запрос:

EXPLAIN
SELECT u.id, u.email, o.id, o.amount
FROM users u
JOIN orders o
    ON u.id = o.user_id
WHERE u.id = 99999;


                                         QUERY PLAN
---------------------------------------------------------------------------------------------
 Gather  (cost=1000.29..12587.81 rows=11 width=36)
   Workers Planned: 2
   ->  Nested Loop  (cost=0.29..11586.71 rows=5 width=36)
         ->  Parallel Seq Scan on orders o  (cost=0.00..11578.33 rows=5 width=19)
               Filter: (user_id = 99999)
         ->  Materialize  (cost=0.29..8.32 rows=1 width=21)
               ->  Index Scan using users_pkey on users u  (cost=0.29..8.31 rows=1 width=21)
                     Index Cond: (id = 99999)
(8 строк)


PostgreSQL покажет, какой план он собирается использовать.



С индексом

Создаём индекс:

CREATE INDEX idx_orders_user_id
ON orders(user_id);

И снова:

EXPLAIN
SELECT u.id, u.email, o.id, o.amount
FROM users u
JOIN orders o
    ON u.id = o.user_id
WHERE u.id = 99999;


 Nested Loop  (cost=4.80..55.70 rows=11 width=36)
   ->  Index Scan using users_pkey on users u  (cost=0.29..8.31 rows=1 width=21)
         Index Cond: (id = 99999)
   ->  Bitmap Heap Scan on orders o  (cost=4.51..47.28 rows=11 width=19)
         Recheck Cond: (user_id = 99999)
         ->  Bitmap Index Scan on idx_orders_user_id  (cost=0.00..4.51 rows=11 width=0)
               Index Cond: (user_id = 99999)
(7 строк)


Теперь можно увидеть, что план изменился, например на:

Nested Loop
├── Index Scan using users_pkey
└── Bitmap Heap Scan on orders
    └── Bitmap Index Scan using idx_orders_user_id
